## 측정 조건

- 보드: NVIDIA Jetson Orin Nano Developer Kit Super, L4T R39.2.1, NV Power Mode 25W, `jetson_clocks` 고정 (시작 시 `--show` 로 GPU 918 MHz, EMC 3199 MHz Min=Max 확인, 끝나면 복원)
- 소프트웨어: CUDA 13.2, TensorRT 10.16.2.10, onnxruntime 1.31.1 (cpu_fp32 전용), Python 3.12.3, numpy 1.26.4, OpenCV 4.8.0
- 코드: git `3385a05` (작업 트리 clean). 도구 `python -m eval.bench_engines`, 일반 터미널에서 실행 (디버거·프로파일러 없음)
- 입력: `data/splits/val.txt` 26장, 640×480 color PNG. 정답지 `data/labels_RGB` (바닥 / 장애물 / 그 외)
- 절차: 모델당 warmup 20프레임 버림 → 26장 × 5회, 회차 사이 30초 쿨다운. p50/p95 는 5회 전체 프레임 기준. 반복 변동% = 회차별 p50 의 (최대−최소)/평균
- 기준 모델(일치율 열): cpu_fp32 = FP32 ONNX 를 onnxruntime CPU 로 같은 세션에서 실행한 결과. mIoU·장애물→바닥% 는 정답지 기준이고, 일치율은 fp32 대비 변환 충실도다. 둘은 다른 지표다
- 엔진: 모두 이 보드·이 TensorRT 로 빌드. TF32 off, workspace 2048 MB. 매니페스트는 각 `.engine.json`
  - gpu_fp32 `models/fast_scnn_fp32.engine`, fp16 `models/fast_scnn_fp16.engine`, ptq_int8 `models/fast_scnn_int8.engine` (엔트로피 캘리브레이션 100장)

## 읽는 법

- 정밀도를 내려도 정답지 기준 정확도는 같다: mIoU 0.931~0.932, 장애물→바닥 1.65~1.67%. qat_int8 은 ptq_int8 과 정확도가 같고 fp32 와 소수점 셋째 자리까지 같다
- qat_int8 의 일치율(99.17%)이 ptq_int8(99.41%)보다 낮은 것은 정상이다. QAT 는 가중치를 다시 학습해 fp32 모델과 멀어진다. 일치율은 정확도가 아니다
- 속도: fp32 → fp16 1.7배, → int8 1.9배 (추론만 기준). ptq 와 qat 의 차이 0.2 ms 는 반복 변동 안이다
- 반복 변동% 는 1회차 효과다. 1회차 p50 이 2~5회차보다 3~4% 느리고 2~5회차는 0.5% 안에 모인다 (예: qat_int8 6.90 / 6.63 / 6.66 / 6.66 / 6.65 ms). warmup 을 전체 26장 한 바퀴로 늘리면 이 열이 1% 아래로 내려갈 것이다
- 엔진 로드 때 TensorRT 가 "Using an engine plan file across different models of devices" 경고를 낸다. 같은 보드·같은 TensorRT 로 빌드한 엔진이고 수치가 10-29 측정과 0.1 ms 안에서 일치하므로 측정에 영향은 없었다
