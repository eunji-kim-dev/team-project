## 읽는 법

- 정밀도를 내려도 정답지 기준 정확도는 같다: mIoU 0.931~0.932, 장애물→바닥 1.65~1.67%. qat_int8 은 ptq_int8 과 정확도가 같고 fp32 와 소수점 셋째 자리까지 같다
- qat_int8 의 일치율(99.17%)이 ptq_int8(99.41%)보다 낮은 것은 정상이다. QAT 는 가중치를 다시 학습해 fp32 모델과 멀어진다. 일치율은 정확도가 아니다
- 속도: fp32 → fp16 1.7배, → int8 1.9배 (추론만 기준). ptq 와 qat 의 차이 0.2 ms 는 반복 변동 안이다
- 반복 변동% 는 1회차 효과다. 1회차 p50 이 2~5회차보다 3~4% 느리고 2~5회차는 0.5% 안에 모인다 (예: qat_int8 6.90 / 6.63 / 6.66 / 6.66 / 6.65 ms). warmup 을 전체 26장 한 바퀴로 늘리면 이 열이 1% 아래로 내려갈 것이다
- 엔진 로드 때 TensorRT 가 "Using an engine plan file across different models of devices" 경고를 낸다. 같은 보드·같은 TensorRT 로 빌드한 엔진이고 수치가 10-29 측정과 0.1 ms 안에서 일치하므로 측정에 영향은 없었다

## QAT 엔진 Q/DQ 배치 수정 (2026-10-30 19:30, 같은 조건·클럭 고정·5회)

최종표에서 qat_int8 이 ptq_int8 보다 추론 0.18 ms(6%) 느린 원인을 층별 프로파일(`python -m deploy.profile_engine`, 클럭 고정)로 찾아 고친 결과.

- **원인은 학습이 아니라 Q/DQ 배치.** quant.py 가 Q/DQ 를 conv 입력·가중치에만 넣어 잔차 블록의 Add 와 fusion 의 Add 입력에는 Q/DQ 가 없었다.
  명시적 양자화에서 TensorRT 는 그 Add 를 INT8 로 못 돌리므로 Add 앞 conv 12개가 FP16 으로 출력하고, 다음 conv 앞에 Half→Int8 변환 커널이 붙었다.
  PTQ(암묵적 양자화)는 TensorRT 가 Add 까지 INT8 로 자유롭게 묶는다. 학습 0 iter 엔진이 같은 층 구성·같은 속도인 것이 증거다.
- **수정.** `quant.quantize_residual_adds` (잔차 블록 6개: skip 경로가 conv.0 의 입력 Q/DQ 를 공유), `quant.quantize_fusion_add`
  (conv_lower_res 출력에 독립 양자화기, scale 은 TRT 캐시의 그 텐서 값). TensorRT 문서의 잔차 블록 권장 배치. qat_train 기본 켜짐 (`--no-quant-adds` 로 옛 그래프).

층별 프로파일 (ms, 클럭 고정, 프로파일러 합 기준 비율)

|---|---|---|---|
| INT8 conv | 40층 0.94 | 28층 0.72 | 38층 0.91 |
| FP16 출력 conv | 없음 | 12층 0.25 | 1층 0.03 |
| Reformat (형식 변환) | 7개 0.11 | 20개 0.29 | 11개 0.11 |
| 전체 (프로파일러 없이) | 1.77 | 1.96 | 1.79 |

- qdq_adds_0iter = 학습 없이 TRT 캐시 scale + Add Q/DQ 만 넣은 엔진, qat_adds = 거기서 300 iter QAT 후 선택 규칙으로 고른 엔진
  (`models/calib_trt_adds/`). cpu_fp32·ptq_int8·qat_int8 은 18:38 최종표와 0.05 ms 안에서 같다
- **속도 격차 해소.** qat_adds 추론 2.98 ms = ptq_int8 2.96 ms. 기존 qat_int8 3.17 ms. 엔진 2.36 → 2.27 MB
- **학습은 이번에도 기여하지 않았다.** 후보 6개(iter 50~300)가 전부 장애물→바닥 기준(학습 전 1.648%)을 넘어 제외되어 iter 0 이 채택됐다
  (iter 100: mIoU 0.9321, 장→바 1.711%). 그래서 qat_adds 와 qdq_adds_0iter 는 같은 ONNX 다 (sha256 동일).
  기존 최종 QAT(iter 100 채택)도 기준을 0.009 pp 차이로 통과한 것이어서, val 26장에서는 둘 다 노이즈 수준이다
- 정확도는 ptq_int8 과 같다 (mIoU 0.931, 장→바 1.65%, fp32 대비 일치 99.41%)
- 같은 가중치·scale 의 로짓 출력 엔진 `models/calib_trt_adds/fast_scnn_qat_logits_int8.engine` 도 함께 만들었다 (카메라 앱 softmax 신뢰도용, 추론 2.7 ms)
- 최종 QAT 엔진을 qat_adds 로 바꿀지는 팀 결정. 바꾸면 최종표 5모델을 한 세션에서 다시 재는 것을 권장
