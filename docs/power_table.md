# Fast-SCNN 정밀도별 전력 소비와 10분 안정성

> 최종 전력 비교: 2026-10-30 20:15  
> 장시간 실행: 2026-11-01 15:06 · Jetson 25W 모드, 클럭 고정

## 1. 확인하려는 질문

속도만 빨라진 모델이 실제로도 전력을 덜 쓰는지 확인했습니다. 이를 위해 각 모델을 **30 fps를 목표로 60초씩 실행**하면서 보드 전력을 측정했습니다. 또 최종 INT8 엔진을 10분간 연속 실행해 속도 저하나 온도 상승으로 인한 스로틀링이 나타나는지도 살펴봤습니다.

최종 측정에서 PTQ INT8과 Q/DQ INT8은 모두 30 fps를 유지했고, 보드 평균 전력은 각각 **6.87 W와 6.86 W**였습니다. 대기 상태(6.24 W)를 뺀 증가분은 0.63 W와 0.62 W입니다. GPU FP32의 증가분 1.65 W보다 낮았습니다. CPU FP32는 30 fps 목표를 달성하지 못했습니다.

이 결과의 핵심은 **INT8이 가장 높은 FPS를 낸다**가 아니라, *30 fps라는 동일한 처리 목표에서 추가 전력이 가장 낮았다*는 데 있습니다.

## 2. 측정 방법과 지표

- 실험은 `bench_table.md`의 최종 성능 비교와 같은 장비·소프트웨어 조건, git `0c5d644`에서 수행했습니다. 성능 벤치가 끝나고 30초 휴식한 뒤 측정을 시작했습니다.
- 전력 모드는 25W, 클럭은 `jetson_clocks`로 고정했습니다.
- `python -m eval.power_sweep`로 모델마다 검증 이미지 26장을 반복 처리해 **목표 30 fps, 60초**를 유지하도록 실행했습니다. 모델 간 휴식은 20초였습니다.
- `tegrastats`를 1초 간격으로 기록했고, 아무 모델도 실행하지 않는 30초를 대기 기준선으로 측정했습니다.
- `VDD_IN`은 보드 전력, `VDD_CPU_GPU_CV`는 CPU·GPU·CV 레일 전력입니다. **대기 대비 +W = 모델 실행 중 보드 전력 − 대기 전력**입니다.
- 프레임당 에너지는 `평균 보드 전력(W) ÷ 실제 fps × 1000`으로 계산한 **mJ/프레임**입니다. 여기에는 대기 전력도 들어갑니다. 따라서 모델만의 순수 추가 에너지와 혼동하지 않아야 합니다.

원본 측정: `results/power_final_1030b/`.

## 4. Q/DQ Add 수정 이후의 전력은 달라졌나

Q/DQ 엔진은 Add 입력의 양자화 배치를 수정해 속도를 개선했습니다. 이 변경이 전력에도 차이를 만드는지 확인하기 위해 같은 조건으로 PTQ INT8과 수정한 `qat_adds`를 다시 비교했습니다.

| 모델 | 실제 fps | 보드 전력 W | CPU+GPU W | 대기 대비 +W | 프레임당 mJ | GPU 사용률 % | 최고 온도 °C | p50 ms | 놓친 프레임 |
|---|---|---|---|---|---|---|---|---|---|
| (대기) | - | 6.23 | 1.20 | - | - | 0.0 | 50.0 | - | - |
| ptq_int8 | 30.0 | 6.94 | 1.57 | 0.71 | 231.3 | 6.6 | 51.3 | 8.72 | 0 |
| qat_adds | 30.0 | 6.93 | 1.57 | 0.70 | 231.0 | 7.2 | 52.1 | 8.72 | 0 |

이 별도 세션에서 PTQ와 `qat_adds`는 각각 6.94 W, 6.93 W였으며 둘 다 30 fps를 달성했습니다. **그래프 변경으로 속도 격차는 줄었지만 측정 가능한 전력 차이는 나타나지 않았습니다.** 이때 두 모델의 p50은 모두 8.72 ms로, 최종 성능표와 다른 시간대의 값입니다.

이 차이를 저장장치 읽기 때문이라고 추정하지는 않았습니다. 이미지를 미리 읽어 캐시를 채워도 8.72 ms였기 때문입니다. 19:43과 19:51 측정에서만 약 8.7 ms가 나왔고, 20:15 최종 세션에는 동일 PTQ 엔진이 6.48 ms로 돌아왔습니다. **원인은 확인되지 않았으므로 추론속도 비교의 기준은 클럭 고정 상태에서 별도 측정한 `bench_table.md`로 둡니다.**

수정 전 QAT 엔진과의 전력 차이도 0.05 W 이내였습니다. 별도 비교 원본은 `results/power_qat_adds_1030b/`입니다.

## 5. 10분 연속 실행에서 안정성이 유지됐나

최종 명시적 INT8 엔진(`models/calib_trt_adds/fast_scnn_qat_int8.engine`)을 `python -m eval.soak_test --minutes 10 --target-fps 30`으로 실행했습니다. 검증 이미지 26장을 반복했으며, 25W 모드와 클럭 고정 상태를 확인했습니다.

| 항목 | 값 |
|---|---|
| 프레임 수 / 실제 fps | 18,001 / 30.0 |
| 프레임 지연 p50 / p95 / 최대 ms (전처리+추론+argmax) | 8.71 / 8.87 / 9.61 |
| 33.3 ms 안에 못 끝낸 프레임 | 0 |
| 처음 1분 p50 → 마지막 1분 p50 | 8.73 → 8.73 ms (변화 +0.0%) |
| GPU 클럭 (고정 918 MHz) | 894~913 MHz, 최고의 90% 미만 샘플 0% → 스로틀링 없음 |
| 최고 온도 tj | 52.2 °C (대기 49.4) |
| 보드 전력 평균 / 최대 | 6.92 / 7.21 W (대기 대비 +0.69 W) |
| RAM 증가 | 192 MB |

총 18,001프레임을 처리하며 실제 30.0 fps를 유지했습니다. 33.3 ms를 넘긴 프레임은 없고, 첫 1분과 마지막 1분의 p50도 모두 8.73 ms였습니다. 최고 온도는 52.2°C였으며 로그에서 클럭 스로틀링은 관찰되지 않았습니다. 따라서 **이 10분 시험에서는 시간 경과에 따른 처리속도 저하를 확인하지 못했습니다.**

다만 이 결과의 p50(8.71 ms)은 앞서 수행한 최종 성능표의 p50과 같은 세션 값은 아닙니다. 실험별 실행 방식과 조건을 함께 보아야 합니다. 원본: `results/soak_int8_1101/`.
