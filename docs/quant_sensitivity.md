# INT8 양자화 정확도 변화의 원인 분석

> 실험일: 2026-10-30 · Fast-SCNN · 검증 데이터 26장  
> 질문: *왜 TensorRT PTQ는 정확도를 유지했는데, 초기 Q/DQ 모델과 QAT 모델은 일부 지표가 나빠졌는가?*

## 1. 먼저 얻은 결론

처음에는 PTQ와 Q/DQ가 모두 INT8인데 결과가 다르다는 점이 문제였습니다. 같은 모델에서 정밀도를 낮추는 과정이라도 **어느 연산에 양자화를 적용하는지, 활성화 scale을 어떻게 정하는지, QAT 중 어떤 가중치가 선택되는지**에 따라 결과가 달라졌습니다.

원인을 분리한 결과는 다음과 같습니다.

1. **초기 Q/DQ의 정확도 저하는 주로 LTD의 `dsconv1`, 특히 depthwise 3×3 Conv의 활성화 양자화에서 발생했습니다.** 그 연산의 활성화 양자화만 해제하면 바닥 IoU가 0.0029 회복됐지만, 가중치 양자화만 해제하면 0.0001밖에 변하지 않았습니다.
2. **PTQ와 초기 Q/DQ의 차이는 활성화 scale로 설명됐습니다.** TensorRT 엔트로피 캐시의 scale을 Q/DQ Conv 45개에 적용하자 mIoU 0.9313, 장애물→바닥 오류 약 1.66%로 PTQ 결과가 재현됐습니다.
3. **초기 EMA QAT에서 장애물→바닥 오류가 증가한 이유는 양자화 자체보다 QAT로 갱신된 가중치였습니다.** 해당 가중치에서 양자화를 꺼도 오류가 2.008%였기 때문입니다. 학습 전 FP32의 1.671%보다 높았습니다.

최종 개발 과정에서는 여기에 한 가지 결론이 더 추가됐습니다. **양자화 scale과 Q/DQ 위치를 바로잡은 뒤에도 학습한 QAT 후보가 선택 조건을 충족하지 못해, 최종 Q/DQ 엔진은 학습 전(iter 0) 가중치를 채택했습니다.** 이 후속 결과는 `bench_table.md`의 2026-10-30 19:57 최종 비교에 기록돼 있습니다.

## 2. 무엇을 지표로 판단했나

분할 모델의 출력은 바닥, 장애물, 그 외 3개 클래스입니다. 여기서는 전체 mIoU 외에도 오류의 **방향**을 구분했습니다.

| 지표 | 이 실험에서 의미하는 것 |
|---|---|
| mIoU | 세 클래스 IoU의 평균. 전체적인 분할 성능 |
| 바닥 IoU | 바닥 영역을 얼마나 정확하게 구분했는지 |
| 장애물→바닥(장→바) | 실제 장애물을 바닥으로 잘못 분류한 비율. 코스트맵에서 통과 가능 영역을 잘못 늘릴 수 있음 |
| 바닥→장애물(바→장) | 실제 바닥을 장애물로 잘못 분류한 비율. 이동 가능한 공간을 줄일 수 있음 |
| FP32 일치율 | 정답지와 무관하게 기준 FP32 모델의 픽셀 출력과 일치하는 비율 |

양자화 원인 분리는 `python -m eval.quant_sensitivity`로 수행했습니다. PyTorch에서 가짜 양자화를 적용하되, Q/DQ ONNX의 scale과 가중치를 읽어 비교했습니다. 통계 구간(CI95)은 **이미지 단위 paired bootstrap 2,000회**로 산출했습니다. 전체 상세 결과는 `results/quant_sensitivity/<모델>/sensitivity.md`에 있습니다.

## 3. 첫 번째 실험: 정확도가 나빠진 층 찾기

### 3-1. 모델 전체의 차이부터 확인

학습 전 체크포인트에서 FP32와 초기 Q/DQ를 비교하면 mIoU는 0.9319→0.9296, 바닥 IoU는 0.8889→0.8859로 낮아졌습니다. 장→바 오류는 1.671%→1.717%로 늘었습니다.

### 3-2. 스테이지별로 양자화를 하나씩 꺼 봄

가장 중요한 행은 `LTD.dsconv1.depthwise_conv`입니다. 해당 Conv만 float로 되돌리면 바닥 IoU가 +0.0034(95% 구간 +0.0011~+0.0059) 증가했습니다. 활성화 쪽만 해제해도 +0.0029였지만, 가중치 쪽만 해제했을 때는 +0.0001이었습니다. 이 차이 때문에 문제를 **가중치 정밀도보다 활성화 scale**에서 찾았습니다.

이 층의 EMA 활성화 scale은 TensorRT 엔트로피 scale의 **2.30배**였습니다. 크기가 지나치게 큰 scale은 작은 활성화값을 표현할 때 해상도를 떨어뜨릴 수 있습니다. 즉, 같은 INT8이라도 실제 수치가 어떤 간격으로 표현되는지가 달랐습니다.

복구 범위를 넓히는 것이 무조건 좋은 것도 아니었습니다. `dsconv1`의 depthwise Conv 1개만 float로 두면 바닥 IoU 0.8893, FP32 일치율 99.57%가 됐고, `dsconv1`의 2개 Conv를 float로 두면 바닥 IoU 0.8892, 장→바 1.633%, 일치율 99.63%가 됐습니다. 세 개 이상으로 넓히면 이 실험에서는 결과가 오히려 나빠졌습니다. LTD 5개 전체를 float로 두면 일치율은 99.83%였습니다.

## 4. 두 번째 실험: 왜 PTQ와 Q/DQ가 달랐나

초기 Q/DQ는 EMA 방식으로 정한 활성화 scale을 사용했고, TensorRT PTQ는 엔트로피 캘리브레이션에서 정한 값을 사용했습니다. 양자화 지점이 비슷해도 각 층에 전달하는 scale이 달랐던 것입니다.

이 차이를 직접 검증하기 위해 두 실험을 했습니다.

- **LTD 5개 Conv의 활성화 scale만** TensorRT 엔트로피 값으로 바꿨을 때, mIoU는 0.9317, FP32 일치율은 99.64%로 회복됐습니다.
- **Conv 45개 전체의 활성화 scale**을 TensorRT 값으로 바꿨을 때, mIoU 0.9313, 장→바 약 1.66%, FP32 일치율 약 99.42%로 PTQ 엔진 결과가 재현됐습니다.

즉 이번 차이의 핵심 원인은 PTQ냐 QDQ냐라는 이름보다 **활성화 scale을 생성한 방식**이었습니다. 원래 실험에서 조정했던 캘리브레이션 이미지 수, 증강 여부, max/EMA 변경만으로는 같은 수준의 문제 해결을 얻지 못했습니다.

## 5. 세 번째 실험: QAT를 했는데 왜 장→바가 더 나빠졌나

초기 **EMA·64장 scale로 학습한 QAT 300 iter 모델**에서는 장→바 오류가 약 2.00%로 증가했습니다. 이것이 실제 양자화 오차인지, 학습 후 가중치 변화인지 구분하기 위해 **학습된 가중치는 유지하고 양자화만 끈 결과**를 확인했습니다.

그 결과 양자화를 끈 모델도 장→바 2.008%였습니다. 같은 가중치의 INT8 결과는 2.003%였으므로 양자화 추가 영향은 거의 없었습니다. 반면 학습 전 모델의 장→바는 1.671%였습니다. 따라서 **오류 증가의 직접 원인은 QAT 동안 변경된 가중치**로 판단했습니다.

가중치 변경 과정에서 바→장 오류는 5.302%에서 4.392%로 줄었습니다. 즉 이 QAT는 바닥을 장애물로 오인하는 오류를 줄인 대신, 장애물을 바닥으로 놓치는 오류를 늘리는 방향으로 움직였습니다. 그동안 mIoU만으로 체크포인트를 선택했기 때문에 이 교환관계를 선택 과정에서 걸러내지 못했습니다.

## 6. 후속 수정: TensorRT scale을 Q/DQ에 적용하고 모델 선택 기준 변경

2026-10-30 오후에는 원인 분석을 실제 학습·배포 코드에 반영했습니다.

**첫째, scale의 출처를 통일했습니다.** `deploy/trt_scales.py`에서 TensorRT 캘리브레이션 캐시(`models/fast_scnn_int8_entropy.calib`, 엔트로피 102장)에 기록된 값을 Conv 45개에 매핑하도록 했습니다. FP32 ONNX의 Conv 노드와 입력 텐서 이름, 모듈 이름과 가중치 모양을 대조해 **45개 전부가 일대일 대응될 때만 적용**합니다. 캐시의 114개 항목 중 나머지 69개는 Conv 입력이 아닌 텐서에 해당하므로 이 매핑에 넣지 않았습니다.

**둘째, QAT 후보 선택 기준을 바꿨습니다.** 학습 전 iter 0을 기준으로 삼아 **장→바 오류가 증가하지 않는 후보 중 mIoU가 가장 높은 모델**을 선택하도록 했습니다. `--obs-floor-tol` 기본값은 0%p이며, `inf`로 설정하면 이전의 mIoU 단독 선택 방식이 됩니다. 후보별 채택·제외 이유는 `qat.selection`에 남깁니다.

**셋째, 실험 재현 정보를 기록했습니다.** `deploy/qat_train.py --trt-calib`으로 scale을 적용하고, `qat.act_calib`에 이전 EMA 값과 대체된 TensorRT 값, 캐시 경로·헤더·SHA-256·이미지 수·엔진 정보를 남기도록 했습니다. `deploy/quant.py`의 scale 버퍼가 CPU에 남아 GPU 캘리브레이션을 막던 문제도 수정했습니다. 이 수정 후 Orin GPU에서 300 iter 학습은 약 64초로 기록됐습니다.

## 7. 종합 판단

이 실험을 통해 **양자화 손상 위치(LTD의 활성화), PTQ와 Q/DQ의 scale 차이, QAT 가중치 변화의 영향을 분리**했습니다. 따라서 초기 Q/DQ를 무작정 더 학습시키는 대신, 먼저 scale을 수정하고, 그다음 앱에 중요한 오류 방향을 선택 조건에 넣는 방식으로 문제를 정리했습니다.

정확도를 다시 확보했다고 해서 곧바로 최종 QAT가 우수한 것은 아닙니다. 최종 채택된 명시적 INT8 엔진은 학습 전 가중치를 사용하므로, **최종 개선 성과는 scale 정합성과 Add Q/DQ 배치 수정**으로 설명하는 것이 정확합니다.

## 8. 실험 재현 명령

아래 명령은 당시 실험에서 사용한 경로와 옵션을 유지했습니다. 경로가 `...`인 예시는 실제 체크포인트 경로로 바꿔야 합니다.

```bash
# 민감도 전체 (stage·block·conv + 누적 8개): 모델당 ~5분 (Jetson GPU)
python -m eval.quant_sensitivity --ckpt checkpoints/best_mIoU_iter_1600.pth --data-root data \
    --qdq-onnx models/fast_scnn_qat_0iter.onnx --out results/quant_sensitivity
# 활성화 scale 을 TensorRT 엔트로피 값으로 바꿔서 측정 + 그 상태의 Q/DQ ONNX 내보내기
python -m eval.quant_sensitivity --ckpt ... --qdq-onnx models/fast_scnn_qat_0iter.onnx --levels --cumulative 0 \
    --trt-scales-for LTD --export-name fast_scnn_qat_0iter_trtscaleLTD --run-name exports
# LTD 5개를 float 로 둔 Q/DQ ONNX
python -m eval.quant_sensitivity --ckpt ... --qdq-onnx models/fast_scnn_qat_0iter.onnx --levels --cumulative 0 \
    --export-convs LTD --export-name fast_scnn_qat_0iter_floatLTD --run-name exports
python -m deploy.build_engine --onnx results/quant_sensitivity/exports/fast_scnn_qat_0iter_floatLTD.onnx --precision qat

# TensorRT 캐시 scale 로 새 0iter 기준 + QAT 300 iter (장→바 조건 선택 포함) → 엔진 → 벤치
python -m deploy.trt_scales --calib models/fast_scnn_int8_entropy.calib --ckpt checkpoints/best_mIoU_iter_1600.pth   # 대응표만
python -m deploy.qat_train --ckpt checkpoints/best_mIoU_iter_1600.pth --data-root data --iters 0 \
    --out models/calib_trt/fast_scnn_qat_0iter.onnx --trt-calib models/fast_scnn_int8_entropy.calib
python -m deploy.qat_train --ckpt checkpoints/best_mIoU_iter_1600.pth --data-root data --iters 300 --lr 1e-4 --batch 4 --seed 42 \
    --out models/calib_trt/fast_scnn_qat.onnx --trt-calib models/fast_scnn_int8_entropy.calib
python -m deploy.build_engine --onnx models/calib_trt/fast_scnn_qat.onnx --precision qat
python -m eval.bench_engines --models cpu_fp32=models/fast_scnn.onnx ptq_int8=models/fast_scnn_int8.engine \
    qdq_trt=models/calib_trt/fast_scnn_qat_0iter_int8.engine qat_trt=models/calib_trt/fast_scnn_qat_int8.engine \
    --images data/images --gt data/labels_RGB --list data/splits/val.txt --out results/qat_trt_select --runs 5 --cooldown 30
```
